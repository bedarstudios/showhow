## Motion basis

The house interaction patterns are Showhow `Button`: background/transform, 150ms, active scale `0.96`, disabled under reduced motion (`src/components/showhow/Button.tsx:7-20`); and `LibraryRow`: color transition at 120ms with reduced-motion transition disabled (`src/components/showhow/LibraryRow.tsx:26-35`). Shared tokens are `--motion-fast: 120ms`, `--motion-base: 180ms`, and `--ease: cubic-bezier(0.2, 0, 0, 1)` (`src/styles/design-tokens.css:177-180`); the proposed ink colors use the existing `--ds-ink` and `--ds-on-panel` tokens (`src/index.css:376-405`). Tailwind is 3.4 (`package.json:181`); `tailwind.config.cjs:1-7` does not override its default transition duration or timing function. Therefore utility transitions without explicit values are recorded as Tailwind defaults (150ms and `cubic-bezier(0.4, 0, 0.2, 1)`), not as measured runtime behavior. `src/lib/utils.ts:1-6` merges classes; the Settings wrapper's `transition-colors` replaces the primitive's `transition-all` (`src/components/showhow/Tabs.tsx:24-32`, `src/components/ui/tabs.tsx:29-35`).

## Progress UIs and #176/T2 dither coverage

`Progress` is the shared converted treatment: 4px pitch, 3px cells, 3 rows / 11px total height, 96px Bayer frontier. On value changes it advances `shown` by 20% of the remaining delta each animation frame and varies the frontier while moving; reduced motion sets the target immediately and draws a static pattern (`src/components/showhow/Progress.tsx:4-17`, `28-33`, `55-76`, `78-115`, `123-139`). It has no fixed duration or CSS timing curve. Its optional `frontier` prop is ignored by the renderer; this audit does not claim Mosaic rendering. Current shared callers:

- **Converted:** Import Video picking stays at 0%, copying follows the byte ratio, and validating/saving displays 100% (`src/components/showhow/ImportVideoSheet.tsx:112-136`); guide generation stage/failure (`src/components/showhow/AiGuidePanel.tsx:234-280`); Agent Brief stage/failure (`src/components/showhow/AgentBriefPanel.tsx:458-513`); Settings recording moves use current/total (`src/components/showhow/SettingsView.tsx:452-467`).
- **Shared component, semantic exception:** workflow-doc generation (`src/components/library/RecordingLibrary.tsx:636-645`) omits a determinate value and `aria-valuenow`; it is indeterminate work and must not be described as 100% complete merely because it uses `Progress`.
- **Not converted custom task-progress bars:** Export sets `aria-valuenow` to the rounded real percentage and `renderFill` width to that percentage (`src/components/ai-edition/ExportDialog.tsx:960-969`); `.renderFill` transitions `width` over `200ms` with `var(--ease)` (`src/components/ai-edition/NewEditorShell.module.css:3183-3188`). Transcription sets `aria-valuenow` from the rounded fraction and inline fill width from the real fraction (`src/components/ai-edition/TranscriptionStatus.tsx:141-168`); its inline style transitions `width` over `200ms linear` (`src/components/ai-edition/TranscriptionStatus.tsx:160-166`). In both, fill distance varies with the reported percentage delta; it is not a fixed spatial movement. They remain dither follow-up candidates only if the owner chooses.
- **Owner-only dither proposal for those two bars:** reuse the shared geometry (4px pitch, 3px cell, 3 rows / 11px, 96px frontier) and keep each real ARIA value. For each semantic value update, draw canvas fill coverage immediately: property `canvas fill coverage`, duration `0ms`, curve `none`, distance `0px`; under reduced motion use the same static exact-value pattern, with no frame interpolation. This proposal describes a possible treatment, not current behavior or a new ticket.
- **Semantic exceptions, not dither candidates:** playback position is a slider (`src/components/ai-edition/TransportBar.tsx:135-150`); device signal is a meter (`src/components/launch/HudDeviceSettings.tsx:42-55`); crop/adjustment values are sliders (`src/components/ai-edition/RightPanes.tsx:3331-3345`, `src/components/ai-edition/Modals.tsx:1009-1019`).
